# 采色精灵 · 原型

纯前端 Web 原型（HTML + Canvas + 原生 JS），无依赖、无构建步骤、不调用任何外部服务。

## 启动

```bash
python3 -m http.server 8765
```

然后打开 http://localhost:8765 。也可以直接双击 `index.html`（file:// 下除「保存画作」在个别浏览器受限外均可用）。

## 操作

| 场景 | 操作 |
|---|---|
| 公园 | `WASD` / 方向键 或点击地面：飞行 · 靠近颜色按 `空格`/`E` 或直接点击它：采进选中瓶子 · `1` `2` `3` 或点击瓶子：切换瓶子 · 飞进右上角「精灵之门」或点「前往精灵空间」 |
| 精灵空间 | 选瓶子 → 点击发光的空白格注入一份颜色 · 「回公园采色」继续下一趟 · 「完成画作」结束 |
| 结束 | 「保存画作」下载 PNG · 「再来一局」/ `Enter` 重开 |

## 文件

- `index.html` 四个状态的 DOM 外壳（开始 / HUD / 结束）
- `style.css` 界面样式
- `game.js` 全部规则、绘制和音效（按「规则常量 → 公园 → 精灵空间 → 主循环」分段）

## 已实现内容

**四个状态**：开始页 → 游玩（公园 ⇄ 精灵空间，可多次往返）→ 结束页（最终画作 + 本局统计）→ 再来一局。

**核心循环（搜索 → 采集 → 注入 → 生长）**
- 公园里 11 个颜色源（郁金香红、樱花粉、喷泉青、银杏黄、湖水蓝、草地绿、薰衣草紫、柿子橙、长椅棕、白鸽白、石子灰），可采的会有闪光；采过后约 1.6 秒恢复，期间半透明并显示进度环。
- 三个瓶子，每瓶容量 3 份。HUD 实时显示液面高度、当前混合色、「纯色 / 混色·n」和组成它的原色小圆点。
- 精灵空间是 6×4 = 24 格的空白画纸，每次注入一份颜色、填满一格。

**瓶子混色系统**
- 同一瓶里的颜色按份数加权混合，使用几何平均近似颜料的减色混合（蓝 + 黄 ≈ 鼠尾草绿，红 + 黄 ≈ 橙，红 + 蓝 ≈ 灰紫），越晚加入的颜色影响越小，所以采集顺序会影响结果。
- 靠近颜色源时，气泡里有预览：`瓶中色 + 新颜色 = 结果`，采之前就能看到会不会混出不想要的颜色。
- 瓶子倒空后恢复为干净空瓶。

**世界生长**
- 长出什么由「格子所在行 × 颜色色系」决定：第 1 行天空（太阳、晚霞、极光、飞鸟、月亮、白云、星空、风筝……），第 2 行远景（各种树、远山、小屋、钟楼、松树），第 3 行中景（花丛、向日葵、灌木、小溪、薰衣草、篱笆、岩石），第 4 行近景（郁金香、蒲公英、青草、池塘、雏菊、南瓜、蘑菇、树桩）。共 11 个色系 × 4 行，约 36 种景物。
- 混色长出的景物名称带 ✦，周围有组成它的原色闪光，花心、屋顶等细节会用到第一种原色。
- **占位规则**：第一份颜色可以种在任意空白处，之后只能种在已有景物上下左右的紧邻格。可种的格子会以当前瓶子的颜色微微发光，悬停时加深。
- 反馈：弹性生长动画 + 底色像水彩晕开 + 粒子 + 景物名称浮字 + 按行区分音高的琶音。

**信息量控制**：顶部只显示一条与当前进度相关的提示（学会后自动消失），右下角只有「已生长 n / 24」一个数字。

**结束条件**：24 格全部长满时自动结束；也可以在瓶子全空时点「完成画作」提前结束。两种情况都会等最后一个景物长完再进入结束页。

## 设计假设（GDD 未写明，由我补全）

1. **一局可以多次往返公园。** GDD 把核心循环写成可重复的，但结局又写成「把带回的颜色放完即结束」。我理解为：一局 = 多趟采集 / 注入，直到画纸填满或玩家主动完成。
2. **容量与粒度**：每瓶 3 份、每次注入 1 份、填满 1 格。一趟最多带 9 份，填满 24 格大约要往返 3 趟。
3. **混色模型**：加权几何平均。GDD 只写了「互相染色」，没有规定颜色学模型。
4. **染色不残留**：瓶子倒空后完全干净。GDD 的「染色累积」我理解为瓶内的混色累积，而不是空瓶也留色（那样更像惩罚）。
5. **颜色 → 景物映射**：色系 + 所在行决定种类，颜色本身决定着色。这是为了让「选什么颜色、种在哪里」都看得出效果。
6. **颜色源可无限采集**，只有短暂的恢复时间，用来防止原地连按，不制造稀缺。
7. **没有倒掉瓶子的操作**：混出不想要的颜色时，只能把它种下（它会长成另一种东西），以此贯彻「无惩罚」。
8. **「数字提示（已注入数量）」**实现为「已生长 n / 24」。

## 与 GDD 的偏差 / 潜在冲突

| # | 内容 | 说明 | 最小修改建议 |
|---|---|---|---|
| 1 | 结束条件 | GDD 写的是「所有携带的颜色都已放置且生长完成」。如果画纸先满、瓶子里还有颜色，本原型仍会结束，剩下的颜色不会用上。 | 若要严格遵守 GDD，可在画纸填满时把剩余颜色作为「最后的点缀」洒满全画面，然后再结束。 |
| 2 | 「后续注入只能在已有内容旁生长」 | 实现为网格四邻接的硬规则，点到不相邻的格子会弹出温和提示。这是一种轻度限制，可能和「无压力」有张力。 | 若试玩中玩家觉得受限，可放宽为「也可以接在对角格」，或者不限制位置，只让新景物向已有景物「长出藤蔓」相连。 |
| 3 | 无分数 | 结束页的统计（景物数、用色数、混色次数、往返次数）只是描述，不做评价；但玩家仍可能把它当分数看。 | 如果发现玩家开始刷数字，可以把统计换成一句根据画面生成的标题或描述。 |

## 建议的试玩问题

1. 你第一次把两种颜色装进同一个瓶子时，是故意的还是不小心的？结果出来时，你是惊喜还是失望？
2. 采集前，你会看气泡里的「+ / =」混色预览吗？它有没有改变你选哪个瓶子？
3. 到第二、三趟时，你会先想好「这趟要带回什么颜色、种在哪里」再出发吗？（观察：是否出现「一瓶一色」或「故意混色」的策略）
4. 注入时，你能猜到这一格会长出什么吗？猜中或猜错哪一种更有意思？
5. 「只能挨着已有景物生长」这条规则，你是感觉在「规划画面」，还是感觉「被限制了」？
6. 有没有哪一刻觉得着急、无聊或不知道下一步该做什么？（观察：在公园里停留的时长、无目的飞行的时间）
7. 看着最终画面，你愿意保存吗？你会怎么给它起名？它让你想起公园里的哪些东西？
8. 再来一局时，你打算做什么不一样的事？
