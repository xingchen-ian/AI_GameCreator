# ADR-0003：单题范围合同与“稍后讨论”机制

- 状态：Accepted
- 日期：2026-10-12
- 决策者：产品负责人 / Codex
- 关联：用户反馈“AI 会引导我直接写出超过当前 question 的内容”

## 背景

设计教练会读取完整 Design State，以便保持一致性。但原 Prompt 只要求“结合全局状态继续追问”，没有定义当前题的硬边界。因此模型可能在 Q1 提前决定玩家目标或机制，并把后续设计混入当前正式答案。

## 决定

为 Q1–Q23 分别建立范围合同，包含“本题必须完成”“本题不要决定”和“可暂存到哪些题”。AI 输出增加 `scopeStatus` 与 `parkedInsights`。越界但有价值的信息进入页面上的“稍后讨论”，不会进入当前题 `suggestedAnswer`。

## 原因

- 保留全局上下文带来的一致性，同时限制当前行动范围；
- 避免新手在没有意识到时提前锁定后续设计；
- 不丢失用户自然提到的有价值想法；
- 让正式答案与每道研究问题保持可解释的一一对应。

## 考虑过的替代方案

### AI 完全看不到其他题答案

没有采用。虽然边界最强，但会失去跨题一致性判断，容易反复询问已经确定的信息。

### 只在 Prompt 中增加一句“不要跑题”

没有采用。没有逐题范围和结构化输出，模型仍可能把相邻问题内容写入答案，页面也无法保存这些想法。

### 自动把越界内容写入目标问题

没有采用。会绕过用户确认，并可能错误解释用户意图。

## 后果

### 正面影响

- 当前题答案更聚焦；
- 后续想法仍被保留且可追踪；
- 用户可以主动决定何时跳转，而不是被 AI 推着前进。

### 代价与风险

- Prompt 和返回结构更复杂；
- 模型可能偶尔错误分类相邻内容，需要通过真实对话继续调优；
- 旧对话不会被追溯重新分类，只有新回复和重新提炼使用新规则。

## 受影响位置

- `lib/protocol/question-scope.ts`
- `app/api/ai/chat/route.ts`
- `app/api/ai/synthesize/route.ts`
- `lib/server/model-provider.ts`
- `components/workflow/workflow-app.tsx`

## 验证方式

- 每道题页面显示“本题边界”；
- 新 AI 回复的正式答案只覆盖当前题；
- 越界内容显示在“稍后讨论”并带目标题号；
- 旧答案和旧对话仍能正常读取。

## 回退方式

保留逐题范围文档，移除 `parkedInsights` 的强制输出和页面区域即可恢复旧交互；现有答案数据无需迁移。
