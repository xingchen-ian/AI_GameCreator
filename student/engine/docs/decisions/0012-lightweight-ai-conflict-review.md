# ADR-0012：轻量化 AI 全局冲突审查

- 状态：Accepted
- 日期：2026-10-17
- 决策者：产品负责人 / Codex
- 调整：[ADR-0011](0011-ai-grounded-conflicts-without-categories.md) 中关于题号的严格模型输出约束
- 后续调整：普通 JSON 输出改由服务端逐项归一化，避免供应商字段轻微偏差导致整步失败，见 [ADR-0014](0014-normalize-non-strict-model-json.md)。

## 背景

全局审查在没有固定冲突分类和默认题号映射之前，已经能够依靠模型对 23 个答案的语义理解定位冲突。后来为了让证据更可核验，模型输出被要求同时满足题号枚举、数量、去重、完整证据和多方案等约束。它提高了格式严格度，但也扩大了 Prompt 和结构化解码负担；当供应商拒绝严格 JSON Schema 时，同一个步骤还可能再次请求宽松 JSON，明显增加等待时间。

## 决定

- 继续由 AI 自主判断冲突和相关题号，不恢复冲突分类、静态题目关系或默认题号；
- 模型只需输出题号、简短冲突证据、玩法影响和 1–2 个修改方向；
- 不再把题号枚举、最少数量和去重作为供应商端 JSON Schema 的硬约束；
- 服务端仍过滤非法和重复题号，并丢弃不足两个有效题号的结果，因此无效目标不会进入数据库或后续修改流程；
- 全局审查直接使用普通 JSON 输出，避免严格 Schema 被供应商拒绝后产生第二次完整请求；
- 全局审查最多返回 6 项，输出预算降为 1400 tokens；单个冲突对话只发送相关原答案和相关 GDD 章节，并缩短历史、输出预算与超时。

## 原因

- 冲突定位的主要能力来自模型阅读完整设计状态后的语义判断，不来自固定分类；
- 题号安全可以在服务端保存边界完成，不必全部压给模型的生成格式；
- 单个冲突已经有明确关联题目，没有必要在每轮对话重复发送全部 23 个答案和完整 GDD；
- 更短的输入和输出能减少等待与超时风险，同时保留用户核验和确认写入机制。

## 后果

- 模型偶尔可能返回非法或不足两个题号；这些项目会被静默过滤，不会用系统猜测的题号补齐；
- 冲突证据比 ADR-0011 初版更简短，但详情页仍展示相关原答案，用户可以直接核验；
- 历史 GDD、冲突、答案和对话结构保持兼容，不需要数据库迁移；
- 具体速度仍受通义服务负载和网络影响，但应用不再因严格 Schema 的 400 响应重复请求审查。

## 受影响位置

- `lib/server/model-provider.ts`
- `app/api/gdd/route.ts`
- `app/api/ai/gdd-review/route.ts`

## 验证方式

- 类型检查、Lint 和生产构建通过；
- 全局审查请求使用普通 JSON 模式，返回结果仍经过本地 Schema 校验；
- 非法题号、重复题号和不足两个有效题号的冲突不会保存；
- 单冲突对话上下文只包含相关答案和相关 GDD 章节；
- 既有冲突和历史 GDD 可以继续读取。

## 回退方式

恢复 `gddIssueSchema` 的题号枚举、数量和去重约束，把两个审查调用恢复为严格 Schema，并恢复原输出预算和完整上下文。无需数据库回退。
