# ADR-0011：删除预设冲突分类，只保存有原题证据的 AI 冲突判断

- 状态：Accepted
- 日期：2026-10-17
- 决策者：产品负责人 / Codex
- 关联：用户提出“审查员既然知道为什么冲突，就应该直接写出涉及的两道或 N 道原题和冲突位置”
- 后续调整：题号仍由 AI 自主识别，但供应商端的严格格式约束已由 [ADR-0012](0012-lightweight-ai-conflict-review.md) 改为服务端过滤。

## 背景

旧实现要求 AI 把每个全局问题归入八种固定 `issueType`。当 AI 没有给出关联题号时，系统再按类型补一组默认题号。这会让分类替代真实证据：一个问题可能被勉强归类，默认题号也可能与当前设计无关。用户真正需要理解的是哪些原始决定互相冲突、哪里不能同时成立，而不是冲突属于哪个抽象类别。

## 决定

- 从 AI 输出 Schema、运行时类型、数据库和 UI 数据中删除 `issueType`；
- 删除 `issueFallbackQuestions`，系统不再根据类型猜测题号；
- 每个冲突必须包含 2–8 个有效且不重复的 `questionIds`；
- `evidence` 必须逐一写出相关题号及其原本主张，并说明这些主张具体为什么不能同时成立；
- 无法提供至少两个原始问题证据的普通缺失、措辞建议或 GDD 写作问题，不保存为冲突；
- 全局审查聊天仍只能从当前冲突已经列出的题目中选择一个修改目标，并明确说明选择原因；
- 冲突详情展示全部关联答案，不再只截取前三项；
- 通过 D1 Schema 迁移删除 `gdd_issues.issue_type`，保留既有冲突的其他字段、ID、状态及历史关联。

## 原因

- 题目与原答案才是可以让用户核验的证据；
- 删除分类减少模型为了满足枚举而错误归类或制造问题的倾向；
- 删除默认题号避免系统把通用猜测伪装成当前项目的真实关联；
- 结构化题号约束仍能让后续修改建议安全地限制在当前冲突范围内；
- 保存全部关联题目可以覆盖两个以上设计决定共同造成的矛盾。

## 考虑过的替代方案

### 保留宽泛分类，但隐藏在 UI 中

没有采用。即使用户看不到，分类仍会影响模型判断和默认题号，不能解决证据被分类替代的问题。

### 完全自由输出，不要求题号

没有采用。自由分析适合对话，但无法安全地同步修改到具体设计节点，也难以让用户核验原始依据。

### 保留默认题号作为失败兜底

没有采用。一个无法定位原题的判断应当被丢弃或重新审查，而不是由系统猜测证据。

## 后果

- 新冲突不再包含或显示类型；
- AI 必须成功定位至少两个原题，否则该项不会进入冲突列表；
- 同一冲突可以关联最多八道题，界面会展示全部原答案；
- 普通“尚未定义”问题不会再混入冲突列表，除非它和另一个已确认决定形成明确不兼容；
- 旧冲突的标题、证据、题号、状态和相关修改记录继续保留。

## 验证方式

- AI 输出结构中不存在 `issueType`；
- 少于两个、重复或非法题号不能通过结构校验；
- 保存层不会用固定映射补题号；
- 点击冲突可看到其全部关联题目和原答案；
- 自动分析明确引用题号并说明不兼容关系；
- 迁移只删除 `issue_type` 字段，其他冲突字段和记录保持；
- Lint、构建与线上 Worker 检查通过。

## 回退方式

新增迁移重新加入可空的 `issue_type` 字段，并恢复枚举、Prompt 和默认题号映射。旧分类列已删除，历史冲突的原分类不能可靠恢复，不应根据标题重新猜测。
