# ADR-0004：通过归档当前项目来重建空白项目

- 状态：Superseded by [ADR-0017](0017-multi-project-workspace.md)
- 日期：2026-10-12
- 决策者：产品负责人 / Codex
- 关联：用户要求“只做重建项目”

## 背景

用户需要重新开始完整设计流程，但不要求分别清空聊天、答案或其他记录。直接删除当前项目会同时删除相关答案、对话、快照、GDD、Build Brief 和 Prototype，误操作风险高，也会损失研究过程数据。

## 决定

“重建项目”采用归档再新建：把当前 active 项目标记为 archived，然后为同一用户创建一个新的空白 active 项目，从 Q1 开始。旧项目的所有关联数据保持不变。当前版本只提供重建入口，不提供清空聊天、永久删除或归档恢复界面。

## 原因

- 满足用户从头开始的直接目标；
- 避免不可恢复的数据删除；
- 保留研究轨迹和版本证据；
- 单一 active 项目使现有工作台不需要引入项目选择器。

## 考虑过的替代方案

### 清空当前项目的所有子表

没有采用。会永久破坏历史数据，并且需要处理多表级联与部分失败。

### 删除项目后自动重建

没有采用。虽然界面结果相似，但删除不可恢复，也不利于后续研究比较。

### 同时增加项目管理和恢复界面

暂未采用。用户明确要求只做重建项目，项目列表和恢复属于额外范围。

## 后果

### 正面影响

- 用户可以安全地获得全新项目；
- 旧设计不会进入新 Design State；
- 旧数据为未来恢复或研究分析保留。

### 代价与风险

- 归档项目会继续占用数据库空间；
- 当前没有界面可恢复或查看归档项目；
- 项目重建由两次数据库写入完成；如果新建失败，下次读取会自动创建新的 active 项目。

## 受影响位置

- `db/schema.ts`
- `lib/server/workspace.ts`
- `app/api/workspace/route.ts`
- `components/workflow/workflow-app.tsx`

## 验证方式

- 点击重建前必须经过确认弹窗；
- 重建后项目 ID 改变、标题恢复为“未命名游戏”、当前问题为 Q1；
- 新项目没有答案、对话、GDD、Build Brief 或 Prototype；
- 旧项目及其关联数据仍在数据库中且状态为 archived。

## 回退方式

取消 `status` 过滤即可重新读取历史项目；若未来增加恢复功能，把目标项目改回 active，并归档当前 active 项目。
