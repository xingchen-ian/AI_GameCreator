# ADR-0008：GDD 审查属于产出流程，右侧持续呈现状态机

- 状态：Accepted
- 日期：2026-10-17
- 决策者：产品负责人 / Codex
- 替代：[ADR-0007](0007-conflict-driven-global-gdd-review.md) 中“右侧固定显示冲突集合”的决定

## 背景

上一版在进入「GDD 全局审查」后，用冲突集合替换了整个右侧面板。这让右侧原有的「状态 / GDD / Build / 试玩」产出链路消失，也把冲突审查看成独立工具，而不是 GDD 生成阶段内部的一项工作。与此同时，中间使用并排卡片、原因卡、影响卡和修改卡重复展示同一问题，阅读层级过多。

## 决定

右侧始终保留四个产出栏目：

`状态 → GDD → Build → 试玩`

- 用户填写 Q1–Q23 时，默认查看「状态」；
- 进入左侧「GDD 全局审查」节点时，自动切换到「GDD」；
- 创建 Build Brief 后切换到「Build」；
- 生成原型后切换到「试玩」；
- GDD 标签不再显示具体版本号，版本信息保留在 GDD 文档内部。

冲突审查只在中间工作区呈现，并简化为：

1. 纵向冲突列表，一行一个冲突；
2. 选中后在一个容器内并列展示最多三个相关节点的原始答案；
3. AI 用不超过 220 个中文字给出简短分析和修改策略；
4. 每轮只提供一条最推荐的完整修改建议；
5. 用户可接受、暂不采用，或继续讨论后重新提炼。

## 原因

- 右侧四栏表达的是从设计状态到可玩结果的产出状态机，应跨所有左侧节点保持稳定；
- 冲突是 GDD 的审查内容，不是与 GDD 并列的新产物；
- 单行列表更适合扫描，避免四张并排卡片抢占空间；
- 原答案并列比“原因 / 影响”两个解释框更容易让用户直接看到不一致；
- 一次只给一条主要建议，可降低新手的选择负担。

## 考虑过的替代方案

### 右侧保留冲突集合，中间展示详细冲突

没有采用。它重复相同信息，并切断「状态 / GDD / Build / 试玩」的连续性。

### 中间继续使用并排冲突卡片

没有采用。冲突数量增加后不利于扫描，卡片中的标题、状态和题号也造成大量视觉噪声。

### 同时提供多个修改建议

没有采用。多个候选方案会增加比较成本；用户仍可通过聊天要求另一种方向。

## 后果

### 正面影响

- 右侧产出流程在所有设计阶段保持一致；
- GDD 审查与 GDD 文档之间的关系更明确；
- 冲突列表更紧凑，原答案和修改建议更容易对照；
- 模型输出更短，每轮成本和阅读负担降低。

### 代价与风险

- 右侧不再承担冲突导航，所有冲突操作集中在中间；
- 旧会话中的长分析仍会保留，新生成内容才遵守新的长度限制；
- 每轮只有一个建议，若用户希望比较方案，需要继续对话。

## 受影响位置

- `components/workflow/workflow-app.tsx`
- `components/workflow/gdd-review-workspace.tsx`
- `app/api/ai/gdd-review/route.ts`
- `lib/server/model-provider.ts`

## 验证方式

- 进入问题节点时右侧默认选中「状态」；
- 进入 GDD 全局审查时右侧仍显示四栏并自动选中「GDD」；
- 冲突列表一行一个，不再使用并排卡片；
- 选中冲突后只显示相关原答案、简短 AI 分析和一条修改建议；
- Build Brief 和原型生成后分别切换到对应栏目；
- 构建、Lint 和线上 Worker 验证通过。

## 回退方式

恢复 ADR-0007 的右侧冲突集合组件和多建议模型约束即可。数据结构没有变化，回退不影响已保存的 GDD、会话或修改记录。
