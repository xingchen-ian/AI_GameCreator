# ADR-0022：对话消息乐观显示并与服务端记录对账

- 状态：Accepted
- 日期：2026-10-22
- 决策者：产品负责人

## 背景

单题设计教练和全局审查对话此前都要等待模型完整返回，才同时显示用户消息和 AI 回复。模型耗时较长时，用户无法确认点击发送是否生效，也容易重复操作。

## 决定

1. 用户发送后，客户端立即用临时 ID 将用户消息加入当前对话，并清空输入框。
2. 同时显示 AI 处理中状态，并自动滚动到最新消息。
3. 服务端成功返回后，删除临时消息，以服务端生成的正式用户消息和 AI 消息替换；根据 ID 去重，避免重复气泡。
4. 请求失败时重新读取工作区，与服务端可能已经保存的用户消息对账；用户手动输入的原文字恢复到输入框，并保留错误提示，便于重试。
5. 服务端数据库仍是唯一持久化事实来源。临时消息不写入答案、研究导出或其他设计状态。

## 原因

- 用户操作需要即时可见反馈，不能被模型响应时间阻塞；
- 服务端会在调用模型前保存用户消息，因此失败后的重新读取比简单删除本地消息更准确；
- 使用临时 ID 替换而不是直接追加，能避免成功响应后同一条用户消息出现两次；
- 不改变 API 和数据库结构，降低对既有研究数据的影响。

## 后果

- 用户发送后会立刻看到自己的消息和 AI 处理状态；
- 网络失败时，界面会以服务端记录为准，并恢复尚未成功提交的输入；
- 当前仍然一次只允许一个 AI 请求，不支持并行发送多条消息。

## 受影响位置

- `components/workflow/workflow-app.tsx`
- `components/workflow/gdd-review-workspace.tsx`

## 验证方式

- 人为延迟 AI 响应时，用户消息应在响应前显示；
- 成功返回后每条用户消息只出现一次；
- 单题对话和全局审查对话行为一致；
- 请求失败时显示错误，并恢复用户输入以便重试；
- typecheck、smoke test、lint 与生产构建全部通过。

## 回退方式

移除临时消息插入和对账逻辑即可恢复等待服务端完整响应后再显示消息；不需要数据库迁移。
