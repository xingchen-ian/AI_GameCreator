# ADR-0017：多项目工作区与两阶段删除

- 状态：Accepted
- 日期：2026-10-19
- 决策者：产品负责人 / Codex
- 替代：[ADR-0004](0004-rebuild-by-archiving-current-project.md) 的单一“重建项目”入口

## 背景

项目表从第一版起就允许同一用户拥有多条记录，但读取层始终自动选择最新的 active 项目，界面只暴露当前项目。原“重建项目”会归档旧项目并创建空白项目，却没有项目列表、切换或恢复入口，导致历史数据虽然仍在数据库中，用户实际上无法管理。

## 决定

- 工作区响应同时返回当前项目和该用户的项目摘要列表；
- 所有修改、AI 审查、GDD 与 Build Brief API 在返回工作区时必须显式携带当前 `projectId`，不得重新猜测“最新项目”；
- 客户端在浏览器本地保存最后打开的项目 ID，刷新后请求该项目；服务端仍验证项目所有权并在项目无效时安全回退；
- 顶部提供统一项目管理器，支持新建、切换和重命名；
- 删除分为两步：active 项目先进入回收站，保留所有子数据；归档项目可恢复，也可在二次确认后永久删除；
- 归档最后一个 active 项目时，系统自动创建空白项目，保证工作区始终可用；
- 项目之间的答案、消息、审查、GDD、Brief 和 Prototype 完全隔离。

## 原因

- 显式 `projectId` 可以避免多项目后一次保存或生成操作返回到另一个项目；
- 两阶段删除降低误删研究数据的风险，同时满足真正删除的需求；
- 浏览器保存选择无需新增用户偏好表，服务端所有权检查仍是最终安全边界；
- 一个集中项目管理器比“重建”按钮更符合用户对新建、修改和删除的理解。

## 受影响位置

- `lib/design/types.ts`
- `lib/server/workspace.ts`
- `app/api/workspace/route.ts`
- 所有调用 `getWorkspace` 的写入 API
- `components/workflow/project-manager.tsx`
- `components/workflow/workflow-app.tsx`

## 验证方式

- 创建两个项目后可在两者间切换，答案和产物互不混合；
- 修改非当前项目名称不会切换当前项目；
- 当前项目刷新后仍保持选中；
- 移到回收站后数据仍可恢复；
- 只有归档项目可以永久删除；
- 归档唯一 active 项目后会创建新的空白项目；
- 所有跨项目请求均通过 ownerId 与 active 状态校验。

## 回退方式

移除项目管理界面和项目列表字段，并恢复默认读取最新 active 项目。项目表与归档记录无需迁移或删除；已存在的多个 active 项目仍可保留，回退版本只会显示其中最新创建的一项。
