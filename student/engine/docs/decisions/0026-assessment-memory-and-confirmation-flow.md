# ADR-0026：Assessment、题目记忆与两次确认流程

- 状态：Accepted
- 日期：2026-10-23
- 决策者：产品负责人 / Codex
- 关联：ADR-0003、ADR-0025、现有单题教练与 Design State 全局审查

## 背景

现有单题教练会在每轮回复时同时追问并生成 `suggestedAnswer`。只要用户尚未编辑答案框，建议就可能自动进入正式答案区域，造成“AI 仍认为信息不足，但页面已经像是可以确认”的语义冲突。

当前上下文只保留最近若干消息；超过预算的旧消息会被截断。已确认答案虽然会进入后续题目的全局上下文，但不会保留该题讨论中用户采用、修改采用、明确拒绝和仍未决定的内容。因此后续问题仍可能重复询问，或把旧的 AI 建议误当成用户决定。

## 决定

### 1. 题目打开时先做 Initial Assessment

打开一道题后，系统先读取其他已确认题目的 Question Memory，并按照当前题目的完成标准判断：

- `complete`：已有记忆足以在不新增用户决定的情况下形成完整 Candidate Answer；
- `partial`：已有记忆只能填写一部分，必须针对关键缺口提问；
- `empty`：已有记忆不足以回答当前题，必须从当前题范围内开始辅助。

`complete` 时直接生成可编辑 Candidate Answer。`partial` 和 `empty` 时保留已知内容作为内部依据，并只针对关键缺口提问，不要求用户从空白重复描述已经确认的信息。

### 2. 每轮用户消息采用 Assessment → Response

用户发送消息后，第一次模型调用只评估：

- Relevance；
- Completeness；
- Specificity；
- Consistency；
- Missing Elements；
- 是否已有足够证据忠实形成 Candidate Answer。

Ready 的定义是“无需替用户新增关键决定即可形成候选答案”，不是“答案已经完善”。第二次模型调用必须服从 Assessment：

- Ready：根据累计讨论生成回复和 Candidate Answer；
- Not Ready：选择一种 scaffolding strategy，提出最多一个关键问题，不生成完整答案。

### 3. Not Ready 不剥夺用户填写权

Not Ready 时页面提供轻量的“直接填写答案”入口。用户可以停止讨论并自行填写，但填写内容仍要走提交审查。

### 4. 第一次确认先审查，不立即写入正式状态

用户第一次点击确认时，依次执行：

1. 宽松的单题完成审查：确认文本确实回答当前题并满足最低完成标准；
2. 若不满足，AI 只解释最关键缺口，答案保持可编辑，不写入 `confirmed`；
3. 若满足，使用当前候选答案与其他已确认题目进行跨题冲突审查；
4. 无冲突时直接正式确认；
5. 有冲突时，AI 在对话中解释冲突、指出题号并给出一个可行修改建议，但不自动修改答案。

### 5. 冲突采用第二次确认覆盖

冲突提示不增加“有意保留”“接受冲突”等状态按钮。用户可以：

- 修改当前答案后重新确认，系统重新审查；
- 跳转到建议修改的其他题目，自行编辑并保存；
- 保持当前文本不变，再次点击确认。第二次确认表示用户已知情并决定继续，系统正式保存且不再重复提示同一组 revision 的冲突。

### 6. 正式确认后生成 Question Memory

只有正式确认成功后，系统才总结该题完整历史并生成 Question Memory。记忆至少区分：

- 最终确认答案；
- 用户明确采用的决定；
- AI 建议后被用户修改采用的决定；
- 用户明确拒绝的方向；
- 约束；
- 未解决问题；
- 尚未被用户接受或拒绝的 AI 建议；
- 来源答案 revision。

未被用户确认的 AI 建议不能作为后续题目的设计事实。

### 7. 单题对话使用滚动摘要

单题上下文超过 token 或 turn 预算后，将较早的完整 turns 压缩成结构化 Working Conversation Summary，并保留最近若干 turns 原文。原始消息继续永久保存；滚动摘要只是模型上下文的派生数据，不等同于正式 Question Memory。

## 原因

- 避免 AI 一边追问一边表现为已经完成答案；
- 复用已经确认的信息，减少让用户重复从空白开始回答；
- 把 AI readiness 与用户最终决定权分离；
- 让冲突审查提供帮助但不成为审批门槛；
- 保留长期对话信息，同时控制上下文成本和噪声；
- 防止未经采用的 AI 建议污染后续设计状态。

## 考虑过的替代方案

### 每轮都生成 suggestedAnswer

没有采用。它无法表达“已知部分”和“关键缺口”的区别，并会过早把 AI 补全内容放进正式答案区域。

### 用户点击确认后立即保存，再异步提示不完整

没有采用。用户需要再次修改时会产生无意义 revision，也会让“不满足本题要求”的内容短暂成为后续题目的正式事实。

### 冲突必须解决后才能确认

没有采用。模型可能误判冲突，最终设计决定权应属于用户。相同内容的第二次确认就是最小化的知情覆盖机制。

### 为冲突增加接受、忽略和有意保留按钮

没有采用。状态按钮会增加前端复杂度；普通 AI 消息、题目跳转和第二次确认已经足够。

## 后果

### 正面影响

- Candidate Answer 出现的时机与 AI 的 readiness 判断一致；
- 新题可以继承已有设计信息；
- 用户始终可以跳过讨论并直接填写；
- 提交前能拦截明显跑题或缺少核心要素的答案；
- 冲突提醒清晰但不会无限重复。

### 代价与风险

- 普通对话每轮增加一次 Assessment 模型调用；
- 初始评估、提交审查、冲突审查和记忆总结需要独立的失败恢复；
- 滚动摘要和 Question Memory 都可能发生摘要漂移，必须保留原始消息、版本和模型调用记录；
- 每题完成标准需要持续通过真实对话校准。

## 验证方式

- 每道题都有明确、可测试的最低完成标准；
- Not Ready 回复不会自动填入正式答案；
- Ready 回复会生成可编辑 Candidate Answer；
- 用户可以从 Not Ready 状态直接填写；
- 未通过本题要求的文本不会成为 confirmed answer；
- 相同 revision 的冲突只提示一次，原文第二次确认可以继续；
- 正式确认后生成的 Question Memory 不把未采用 AI 建议当作设计事实；
- 长对话压缩后仍保留最近完整 turns 和可追溯的原始消息。

## 回退方式

保留新表和研究记录，关闭 Initial Assessment、提交前审查与滚动摘要开关；单题聊天可以退回一次模型调用和手动“AI 重新提炼”，现有正式答案无需迁移。
