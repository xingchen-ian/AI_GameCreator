# ADR-0023：跨题暂存必须来自用户原文并可带入目标问题

- 状态：Accepted
- 日期：2026-10-22
- 决策者：产品负责人 / Codex
- 关联：[ADR-0003](0003-question-scope-and-parking-lot.md)

## 背景

“稍后讨论”原本完全信任模型返回的 `parkedInsights`。模型在一次 Q1 答案提炼中自行提出了关于过程与判断的追问，又把这句追问标记为应前往 Q2 的跨题内容。界面只验证题号是否合法，因此显示了并非用户提出的“去 Q2”。此外，用户点击“去 Qx”后，原跨题文字没有进入目标问题输入框，需要重新输入。

## 决定

1. `parkedInsights.content` 必须是用户在当前问题对话中说过的连续原文，不能是 AI 的追问、推断、建议或补充。
2. 模型 Prompt 明确要求逐字复制用户原文；Prompt 版本升级为 `coach-v3` 与 `answer-synthesis-v3`。
3. 服务端在持久化之前，用当前问题的用户消息验证每条暂存内容；无法找到原文证据、目标题号无效或指回当前题时直接丢弃。
4. 客户端读取历史结构化数据时再次执行相同验证，避免旧的错误数据继续显示。
5. 点击“去 Qx”只执行问题切换，并将该段用户原文预填到目标问题的聊天输入框；不自动发送，也不自动写入正式答案。

## 原因

- 跨题暂存代表“用户已经提出但决定稍后处理的内容”，来源必须可验证；
- Prompt 约束不能单独承担数据完整性责任，应用层需要确定性的校验边界；
- 预填而不自动发送保留用户编辑与确认权，同时减少重复输入；
- 客户端二次过滤可以立即保护已有项目，无需修改或迁移历史数据库记录。

## 考虑过的替代方案

### 只修改 Prompt

没有采用。模型仍可能偶发违反语义要求，错误结果会继续进入数据库和界面。

### 允许 AI 自己生成“推荐去 Qx”的追问

没有采用。这会混淆“用户素材暂存”和“AI 导航建议”的来源。如果以后需要 AI 导航，应使用独立字段和视觉样式。

### 点击后自动发送

没有采用。自动发送会让导航动作产生模型调用和永久对话记录，用户无法先修正上下文。

## 后果

- AI 自己生成的问题不会再出现“去 Qx”；
- 合法跨题内容必须保持用户原文，因此可能比 AI 改写后的表达更口语化；
- 点击跳转后，用户可以编辑预填文字再发送；
- 旧记录保留在研究数据中，但不再通过当前界面错误展示。

## 受影响位置

- `lib/design/parked-insights.ts`
- `app/api/ai/chat/route.ts`
- `app/api/ai/synthesize/route.ts`
- `components/workflow/workflow-app.tsx`
- `tests/smoke/parked-insights.test.ts`

## 验证方式

- 用户原文中的跨题片段能够显示，并指向合法的其他问题；
- AI 自行生成但用户没有说过的追问被过滤；
- 当前题和不存在的题号不能作为暂存目标；
- 点击“去 Qx”后，目标问题聊天框预填对应用户原文但不自动发送；
- typecheck、smoke test 与生产构建通过。

## 回退方式

移除服务端和客户端的原文验证，并恢复 `selectQuestion` 清空草稿的行为；不需要数据库迁移。
