# ADR-0029：完整研究可观测性与校验备份

## 状态

Accepted，2026-10-24。

## 背景

已有研究记录能够保存答案、对话、AI 建议、模型元数据和主要设计产物，但不能复现模型实际收到的 Prompt，也不能准确分析参与者的操作路径。部分已入库产物没有进入批量导出，SQLite 也只有手工导出而没有自动备份和完整性验证。

## 决定

- 每个逻辑模型调用保存全部实际 HTTP 尝试，包括严格 Schema 请求、JSON 降级和修复请求的完整 JSON 请求体、原始响应、状态码、耗时和错误；绝不保存 Authorization header 或 API Key。
- 浏览器按 session 记录题目打开/关闭与停留时间、按钮和链接点击、答案框显隐、AI 候选可见、视图切换、页面载入类型、前后台和网络状态；不采集未提交输入框内容。
- 研究导出格式升级到 v4，补入 Build Brief、GDD Issue、GDD Review Change、Design Snapshot、Prototype Version、界面事件和模型调用尝试。
- `study:start` 在启动前、固定间隔和正常结束时使用 SQLite 在线备份 API；源库和备份都执行 `integrity_check`，并为每份备份生成 SHA-256 清单。
- 管理员页显示最近备份状态，批量导出改为可捕获错误的下载流程。
- 备份按白名单文件名和保留数量轮转；默认保留 20 份，每 15 分钟备份一次。

## 原因

模型快照允许在提示词、模型版本或服务商行为变化时复查一次判断的实际输入输出。行为日志把“系统结果”与“用户如何到达结果”连接起来，同时避免记录未提交草稿。SQLite 原生在线备份比直接复制 WAL 数据库文件安全，完整性检查与哈希清单能尽早发现损坏或不完整副本。

## 替代方案

- 只保存 Prompt 模板版本：体积较小，但无法重建动态上下文，因此拒绝。
- 录屏或全量 DOM/键盘记录：信息更丰富，但隐私风险和分析成本过高，因此拒绝。
- 直接定时复制 `.db` 文件：WAL 写入期间可能得到不一致副本，因此拒绝。
- 立即迁移云数据库：能提供异地耐久性，但超出当前本机小规模研究的部署边界，暂不采用。

## 后果

- 数据库和导出体积会明显增加，尤其是完整模型响应；研究者需要关注磁盘空间和数据保留政策。
- 请求快照和对话可能包含参与者提供的内容，必须按研究数据的敏感等级保存和传输。
- 本机备份不能抵御整机磁盘损坏；正式测试仍应把 `data/backups` 同步到独立介质或受控云存储。
- 页面关闭时浏览器的 keepalive 请求仍可能被浏览器丢弃，但周期性批量上传把最大未上传窗口限制在约两秒。

## 受影响位置

- `db/schema.ts`
- `lib/server/model-provider.ts`
- `app/api/events/route.ts`
- `lib/client/use-study-events.ts`
- `lib/server/research-export.ts`
- `scripts/backup.mjs`
- `scripts/study-start.mjs`
- `components/access/admin-research.tsx`

## 验证与回退

- 对成功、严格模式 400 降级、超时和修复分别确认快照存在且不含 API Key。
- 模拟题目切换、答案框显隐、离线/恢复和刷新，确认导出按 session 和时间排序。
- 对实际 SQLite 运行备份，重新打开副本执行 `integrity_check` 并核对 SHA-256 清单。
- 回退时可停止前端事件上传和定时调度，但保留新增列与表，避免破坏已有研究数据。
