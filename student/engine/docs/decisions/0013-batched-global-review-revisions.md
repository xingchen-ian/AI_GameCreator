# ADR-0013：一轮全局审查支持集中完成多项修改

- 状态：Superseded by [ADR-0016](0016-design-review-before-gdd.md)
- 日期：2026-10-18
- 决策者：产品负责人 / Codex
- 调整：[ADR-0010](0010-ai-review-instead-of-mechanical-dependency-propagation.md) 中“答案变化后所有旧建议立即失效”的策略

## 背景

一轮 GDD 全局审查可能同时找出三到四个冲突。旧实现应用第一条问题答案修改后，会立即把 GDD 标记为 `stale`、把同一版本所有未应用建议标记为 `stale`，并禁止继续调用审查对话。用户因此无法依次处理同一轮剩余冲突，只能重新生成 GDD、再次等待全局审查，形成频繁的生成循环。

## 决定

- 问题答案写入后，GDD 和 Build Brief 仍标记为 `stale`，表示它们不能被确认或用于构建；
- `stale` GDD 的本轮冲突清单仍可继续浏览、讨论和生成修改建议；
- AI 在集中修订状态下读取相关题目的最新答案。如果旧冲突已被前一项修改消除，应返回说明和空修改建议；
- 一条答案变化时，只把目标为同一道题的其他未应用建议标记为 `stale`，保留针对其他题目的建议；
- 每条建议应用前继续比较 `beforeContent` 与当前答案。若目标答案已经变化，该建议单独失效并拒绝覆盖；
- 用户处理完本轮冲突后，主动点击“完成修改，重新审查”，系统再基于全部最新答案生成新 GDD 和新冲突集合；
- 新 GDD 保存时，上一轮尚未采用的建议仍统一失效。

## 原因

- 冲突审查天然是一组待处理事项，应用一项不应立即中断整轮工作；
- GDD 的版本过期与审查工作区是否可继续使用是两个不同概念：前者阻止确认和构建，后者可以作为本轮修改清单继续存在；
- `beforeContent` 提供逐条乐观并发保护，能防止旧建议覆盖已变化的同一答案；
- 最后统一重新审查可以减少反复生成的时间和模型费用。

## 后果

- 用户可以连续处理多个冲突，再统一重新生成；
- 已过期 GDD 仍不能确认或生成新的 Build Brief；
- 某条建议可能因其他修改在语义上不再必要，因此 AI 被要求读取最新相关答案并允许返回“冲突已消除”；
- 两条建议若修改同一道题，第一条写入后，其余同目标建议会失效；
- 不需要数据库迁移，历史答案、GDD、冲突和修改记录保持兼容。

## 受影响位置

- `app/api/ai/gdd-review/route.ts`
- `app/api/workspace/route.ts`
- `components/workflow/gdd-review-workspace.tsx`
- `components/workflow/workflow-app.tsx`

## 验证方式

- 应用一个冲突的答案修改后，GDD 变为 `stale`，但其他冲突仍能打开和对话；
- 针对不同答案的未应用建议继续保持 `proposed`；
- 针对同一答案的旧建议变为 `stale`，不能覆盖新内容；
- 集中修订状态仍不能确认 GDD 或继续 Build；
- 点击“完成修改，重新审查”后生成新版本，并使上一轮剩余建议失效；
- Lint 与生产构建通过。

## 回退方式

恢复 `stale` GDD 的对话阻断条件，并在任意答案修改后把同一版本的全部 `proposed` 建议更新为 `stale`。无需数据库回退。
