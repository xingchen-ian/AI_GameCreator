# ADR-0001：Workflow 与 Agent 分离为独立项目

- 状态：Accepted
- 日期：2026-10-11
- 决策者：产品负责人 / Codex
- 关联：[V1 产品架构](../v1-product-architecture.md)

## 背景

项目同时存在“由 Agent 自主推进设计”和“用户沿可视化流程逐项完成设计”两种产品方向。二者的交互模型、状态结构与用户控制程度不同。如果继续放在同一目录和同一产品入口，容易把自主 Agent 的行为误当成 Workflow 的固定行为，也会让实验结果难以比较。

## 决定

Game Design Workflow 作为独立项目存在于 `game-workflow`，不复用或覆盖已有 Agent 项目。六阶段、23 题被定义为可跳转、可回退的设计 protocol，而不是固定对话脚本。

## 原因

- 保持两个研究方向的变量独立，便于比较；
- Workflow 强调用户确认和可视化状态，Agent 强调自主判断；
- 独立代码库可避免数据模型、Prompt 和部署互相污染。

## 考虑过的替代方案

### 在 Agent 项目里增加 Workflow 模式

没有采用。短期代码复用更多，但会让两个产品共享状态和行为边界，后续难以解释实验差异。

### 仅制作无后端原型

没有采用。无法验证身份、持久状态、版本和真实 AI 调用。

## 后果

### 正面影响

- 产品边界清晰；
- Workflow 可独立迭代和部署；
- 用户对每一步设计决定保有确认权。

### 代价与风险

- 两个项目可能需要重复实现部分基础能力；
- 跨项目能力需要显式设计接口，不能依赖隐式共享。

## 受影响位置

- 整个 `game-workflow` 项目
- `lib/protocol/stages.ts`

## 验证方式

Workflow 可在不读取或修改 Agent 项目的情况下独立构建、部署和保存用户项目。

## 回退方式

若未来需要统一入口，使用上层导航或共享服务连接两个独立应用，不直接合并内部状态模型。
